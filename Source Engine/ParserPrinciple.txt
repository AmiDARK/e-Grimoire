Here are the details of what I think, should be good to build an "Universal Creation & Emulation System" :


1. The parser do a 1st pass to detect all variables availables in the Source Code.
It should detect 2 types of variables and stores them in list (global, and uses function/methods names for other lists referencies
- Global (in the main source code)
- Per Function/procedure (in specific Function/Procedure)


2. Parser start to create "Final Source Code".


3. Parser add Header_coldStart file at the beginning of source code


4. Parser add all global variables using the following methods and scheme from var_macros file :
	4.1 : Inject 'seDataReset" MACRO to initialize data structure container
	4.2 : Inject 'add(Arr)Variable %VARNAME%,%VARTYPE%' MACRO for each global simple variable with
		%VARNAME% = name of the variable and %VARTYPE% = type of variable ( || combinations of specified
		'available_variables_type:' in var_macros file)
		- use : 'addVariable %VARNAME%, %VARTYPE%' for Integer, Float and String
		- use : 'addArrVariable %VARNAME%, %VARTYPE%' for Dim(fixed_size) or dynamic Array() of integer, float and String
	4.3 : Inject 'endDatas %VARSIZENAME%' MACRO to close the data structure Container with %vARSIZENAME% = name
		of the variable that contain the size of the structure
	4.4 : Inject 'buildDatas %VARSIZENAME%' MACRO to allocate memory for global variables use the sams %VARSIZENAME%
		than in 4.3 step
	4.5 : Inject 'SaveAsGlobal' to tell the engine that this structure contains all global variables


5. The parser start the disassembly of global source code lines in simple bricks (not functions/procedures that will be added
				at the end of the source code) and insert them in the source code:

		For example : Screen Open 0, 320 + XSCROLLSIZE, 200 + YSCROLLSIZE, 256, Lowres + Laced		
		- Should result to the following operations :
				 	0
					320 + XSCROLLSIZE
					200 + YSCROLLSIZE
					256
					Lowres + Laced (Lowres and Laced are System Variables I Will explain how to load them after
					Screen Open 0, TEMPVAR1, TEMPVAR2, 256, TEMPVAR3
		- The Source Code result generated by the parser should uses the following Macros:
					PushSysVar Lowres 		(Copy system constant Lowres in stack--)
					PushSysVar Laced                (Copy system constant Laced in stack--)
					ExecuteOR,2  			(Will do a bit or operation (||) from 2 pushed ++stack datas, result -> 5th method argument to --stack)
					PushInt 256			(Push 4th method argument to Stack--)
					PushInt 200			(Copy 320 in stack--)
					PushIntGlobal YSCROLLSIZE 	(Copy YXSCROLLSIZE var in --stack)
					ExecuteAdd,2			(will add the 2 pushed ++stack datas, result -> 3rd method argument to --stack)
					PushInt 320 			(Copy 320 in --Stack)
					PushIntGlobal XSCROLLSIZE 	(Copy XScROLLSIZE var in --stack)
					ExecuteAdd,2 			(will add the 2 pushed ++stack datas, result -> 2nd method argument to -Stack)
					PushInt 0 			(Push 1st method argument to --Stack)
					seScreenOpen			(Will call the Source Engine screen open with all parameters available in Stack++)
		It show that, concerning Source Engine methods calls, stack stores parameters in their reversed order in memory, put get them in their
		definition order.

		It is also important that the parser handle mathematic operations with priorities.
		MACROS ExecuteAdd,COUNT; ExecuteSub,COUNT; ExecuteMul,COUNT; ExecuteDiv,COUNT; ExecuteOR,COUNT, EXecuteAND,COUNT
		are macros that execute primitives operations directly in the parameters stacks. It is made to win performancies in
		simple operations. COUNT value is here to tell how many variables are involved in the operation that will be done from
			the last variable in the stack (current one) to previous ones.
			For Example, to do a 5 / 2 operation you should do :
					PushInt 2
					PushInt 5
					ExecuteDiv,2
			To do 5 - 4 :
					PushInt 4
					PushInt 5
					ExecuteSub,2
			Adding numbers is the only operation that is not dependant to data pushing order.
	

6. When a complex operation (with parenthesis or prioritized operations is requested or is done in an existing method, the parser can use temporar
		datas slots:
		
		For example : MYINT = Abs( -25 ) - 5
		- SHould result to the following operations :
				Abs( -25 )
				TEMPVAR=
				TEMPVAR1 - 5
				MYINT=
		- The source code result generated by the parser should uses the following Macros :				
					PushInt -25			( Push 1st method argument to stack++ )
					seAbs 				( Call the Abs() method from Maths.s/seAbs, get data in --Stack, push result in stack++ )
					getTempVar 1			( TEMPVAR1 = --Stack )
					PushInt 5			( Push Integer 5 (2nd method argument to stack++)
					PushTempVar 1 			( Push TEMPVAR1 to stack++ (2nd method argument to stack+++)
					ExecuteSub,2			( Execute TEMPVAR1 - 25 (to --Stack) = Abs( -25 ) - 5 = Result in stack++)
					GetGlobalInt MYINT 		( MYINT = result in --Stack)
